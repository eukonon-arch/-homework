## 1. Описание данных и постановка задачи

### Датасет
- **Источник**: Bike Sharing Dataset (day.csv)
- **Период**: 01.01.2011 — 31.12.2012 (731 наблюдение)
- **Частота**: ежедневная (freq='D')
- **Целевая переменная**: `cnt` — общее число аренд велосипедов за день

### Переменные
| Переменная | Описание |
|-----------|----------|
| `dteday` | Дата |
| `season` | Сезон (1-зима, 2-весна, 3-лето, 4-осень) |
| `yr` | Год (0=2011, 1=2012) |
| `mnth` | Месяц (1-12) |
| `holiday` | Праздник (0/1) |
| `weekday` | День недели (0=Вс, 6=Сб) |
| `workingday` | Рабочий день (0/1) |
| `weathersit` | Погода (1-ясно, 2-облачно, 3-дождь, 4-ливень) |
| `temp` | Температура (нормализованная, 0-1) |
| `atemp` | Ощущаемая температура (нормализованная) |
| `hum` | Влажность (нормализованная) |
| `windspeed` | Скорость ветра (нормализованная) |
| `casual` | Аренды незарегистрированными пользователями |
| `registered` | Аренды зарегистрированными пользователями |
| `cnt` | **Целевая**: общее число аренд |

### Постановка задачи
| Параметр | Значение |
|----------|----------|
| Тип задачи | Одномерное прогнозирование (univariate forecasting) |
| Горизонт | h = 14 дней |
| Режим | Офлайн |
| Метрики | RMSE, MAE, MAPE |
| Бейзлайн | Naive, SeasonalNaive, HistoricAverage |
| Стат. методы | ≥5 (ARIMA, ETS, Theta, Holt, HoltWinters — авто + ручные) |

## 2. Задача №1: EDA

### Базовый анализ данных
```
Наблюдений: 731
Период: 2011-01-01 — 2012-12-31
y (cnt): min=22, max=8714, mean=4504.3, std=1937.2
Пропуски: отсутствуют
```

### ADF-тест на стационарность
| Тест | Statistic | P-value | Результат |
|------|-----------|---------|-----------|
| Исходный ряд | -1.8774 | 0.3427 | **Нестационарный** (p > 0.05) |
| 1-я разность | -11.7788 | 1.05e-21 | **Стационарный** (p < 0.05) |

**Интерпретация**: Ряд содержит единичный корень и требует дифференцирования (d=1) для ARIMA-моделей. Первая разность полностью стационарна.

### Сезонная декомпозиция (period=7)
- **Тренд**: восходящий в 2011–2012 с замедлением к концу периода
- **Сезонность**: явная недельная (пики в выходные/будни)
- **Остатки**: содержат автокорреляцию, что указывает на неиспользованную информацию

### Корреляционный анализ
| Переменная | Корреляция с `cnt` |
|------------|-------------------|
| `registered` | 0.95 (очень сильная) |
| `temp` | 0.63 (сильная) |
| `atemp` | 0.62 (сильная) |
| `casual` | 0.47 (умеренная) |
| `hum` | -0.33 (обратная) |
| `windspeed` | -0.24 (слабая обратная) |

### Выводы по EDA (Задача №1)
1. Ряд **нестационарен**, требует дифференцирования (d=1 в ARIMA)
2. Присутствует **недельная сезонность** (period=7)
3. **Тренд восходящий** с сезонными пиками в тёплые месяцы
4. Сильная корреляция с `registered` (0.95) и `temp` (0.63)
5. Данные **полные** (без пропусков), 731 наблюдение
6. Подготовлены данные для дальнейшего анализа: `ds` (дата), `y` (cnt)

## 3. Задача №2: Статистические методы (statsforecast)

### Используемые модели (10 методов)

| Модель | Тип | Параметры | Обоснование |
|--------|-----|-----------|-------------|
| AutoARIMA | Стат. (авто) | Автоматический подбор (p,d,q)(P,D,Q) | Стандарт для ВР с трендом |
| ARIMA(1,1,1) | Стат. (ручной) | order=(1,1,1), season_length=7 | Ручная настройка на основе ADF (d=1) |
| AutoETS | Стат. (авто) | Автоматический error/trend/season | Аддитивная/мультипликативная декомпозиция |
| Holt | Стат. (ручной) | season_length=7 | Учёт тренда и сезонности |
| AutoTheta | Стат. (авто) | Автоматический theta | Победитель M3-конкурса |
| Theta | Стат. (ручной) | season_length=7 | Ручной Theta |
| HoltWinters | Стат. (ручной) | season_length=7 | Тренд + сезонность + сглаживание |
| HistoricAverage | Бейзлайн | Среднее по истории | Простейший бейзлайн |
| SeasonalNaive | Бейзлайн | season_length=7 | Последнее значение того же дня недели |
| Naive | Бейзлайн | — | Последнее наблюдение |

### Анализ остатков лучшей модели (на тесте: HistoricAverage)
- Распределение остатков: смещено вправо, не полностью нормальное
- ACF остатков: значимая автокорреляция на лагах 1-3
- **Интерпретация**: Модель не полностью захватывает структуру ряда, есть потенциал для улучшения

### Выводы по статистическим моделям (Задача №2)
1. **На тесте** лучшая — HistoricAverage (RMSE=2527.79), но это может быть случайностью из-за специфики тестового окна
2. **По CV** лучшая — ARIMA(1,1,1) (RMSE=882.39), что надёжнее, т.к. усреднено по 3 окнам
3. Простые бейзлайны конкурентоспособны на тесте — ряд имеет слабую предсказуемую структуру
4. Сложные модели (AutoETS, HoltWinters) проигрывают — возможны переобучение на шуме
5. CV показывает лучшую обобщающую способность ARIMA и Theta-моделей
6. Остатки содержат автокорреляцию → есть неиспользованная информация

## 4. Задача №3: ML и DL методы

### Feature Engineering
Для ML-моделей созданы 20 признаков:
- **Календарные**: day_of_week, day_of_month, month, year, day_of_year, is_weekend
- **Лаговые**: lag_1, lag_2, lag_3, lag_7, lag_14, lag_21, lag_28, lag_30
- **Скользящие статистики**: rolling_mean(7,14,28), rolling_std(7,14,28)

### ML-модели (рекурсивный прогноз)

| Модель | Параметры | Обоснование |
|--------|-----------|-------------|
| RandomForest | n_estimators=100, max_depth=None | Устойчив к переобучению, не требует масштабирования |
| XGBoost | n_estimators=200, max_depth=5, lr=0.1 | Градиентный бустинг — лидер на табличных данных |
| LightGBM | n_estimators=200, max_depth=5, lr=0.1 | Быстрый бустинг с гистограммами, лучшая производительность |

### DL-модели (NeuralForecast)

| Модель | Параметры | Обоснование |
|--------|-----------|-------------|
| N-BEATSx | input_size=28, max_steps=50 | State-of-the-art для ВР, обратимые остаточные связи |
| N-HiTS | input_size=28, max_steps=50 | Иерархическая интерполяция, мультимасштабность |
| LSTM | input_size=28, max_steps=50 | Рекуррентная сеть для последовательностей |

### Результаты (h=14)

| Модель | Тип | RMSE | MAE | MAPE% |
|--------|-----|------|-----|-------|
| **LightGBM** | ML | **2442.96** | 2106.92 | 183.08 |
| XGBoost | ML | 2453.50 | 2166.64 | 184.71 |
| RandomForest | ML | 2675.62 | 2357.42 | 202.46 |
| NBEATSx | DL | 2767.46 | 2414.29 | 211.71 |
| NHITS | DL | 2860.30 | 2480.90 | 219.20 |
| LSTM | DL | 3152.89 | 2801.63 | 234.05 |

### Сравнение с бейзлайном и статистическими моделями

| Ранг | Модель | Тип | RMSE | Примечание |
|------|--------|-----|------|------------|
| 1 | **LightGBM** | ML | **2442.96** | Лучший результат |
| 2 | XGBoost | ML | 2453.50 | Близко к LightGBM |
| 3 | HistoricAverage | Стат. | 2527.79 | Лучший среди статистических (тест) |
| 4 | Naive | Стат. | 2561.43 | Простой бейзлайн |
| 5 | RandomForest | ML | 2675.62 | Хорошо, но уступает бустингу |
| 6 | AutoARIMA | Стат. | 2779.37 | Лучше по CV |
| 7 | NBEATSx | DL | 2767.46 | Лучший среди DL |
| 8 | NHITS | DL | 2860.30 | |
| 9 | ARIMA(1,1,1) | Стат. | 2882.77 | Лучше по CV |
| 10 | SeasonalNaive | Стат. | 2894.87 | |

### Выводы по ML/DL (Задача №3)
1. **LightGBM — абсолютный лидер** (RMSE=2442.96), превзошёл все статистические и DL-модели на тесте
2. **ML > DL**: Градиентный бустинг показал лучшие результаты, что типично для малых выборок (n=731)
3. **XGBoost** — ближайший конкурент LightGBM (разница RMSE < 11)
4. **NBEATSx** — лучшая DL-модель, но уступает ML из-за малого объёма данных
5. **LSTM** показал худший результат — рекуррентные сети требуют больше данных и тонкой настройки
6. Feature engineering (лаги, скользящие статистики, календарные признаки) значительно улучшил качество ML-моделей
7. Все модели использовали **рекурсивный прогноз** для многошагового предсказания
